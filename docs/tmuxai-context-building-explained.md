# TmuxAI Context Building - Step by Step

This document explains exactly how TmuxAI builds and sends context to the AI API on each request.

## Overview

Every time you send a message to TmuxAI, it builds a complete conversation array and sends it to the OpenRouter API. The AI gets the ENTIRE conversation history plus current context every single time.

## Step-by-Step Context Building Process

### Step 1: User Input Received
- User types a message in TmuxAI
- TmuxAI receives the input in `process_message.go:ProcessUserMessage()`

### Step 2: Mode Selection (`process_message.go:46-59`)
TmuxAI determines which system prompt to use based on current mode:

```go
var history []ChatMessage
switch {
case m.WatchMode:
    history = []ChatMessage{m.watchPrompt()}
case m.GetAgenticMode():
    history = []ChatMessage{m.agenticPrompt()}
default:
    history = []ChatMessage{m.chatAssistantPrompt(m.ExecPane.IsPrepared)}
}
```

### Step 3: System Prompt Building (for Agentic Mode)

When in agentic mode, `prompts.go:agenticPrompt()` builds the system prompt in this exact order:

#### 3a. Base System Prompt (`prompts.go:12-41`)
```go
builder.WriteString(m.baseSystemPrompt())
```

**What gets added:**
- TmuxAI identity and role
- XML tool definitions (`<ReadFile>`, `<ExecCommand>`, etc.)
- Basic behavior rules
- File reading guidelines
- Conversational tone

**BUT** if you have `config.prompts.base_system` set, it uses that instead:
```go
if m.Config.Prompts.BaseSystem != "" {
    basePrompt = m.Config.Prompts.BaseSystem
}
```

#### 3b. Agentic Instructions (`prompts.go:64-119`)
```go
agenticPromptText := fmt.Sprintf(`
Your primary function is to assist users by interpreting their requests...
==== PANE TARGETING SYSTEM ====
You can target specific panes using their IDs...
<ExecCommand pane_id="%%1">: Use this to execute shell commands...
<ReadFile pane_id="%%1">: Use this to read file content silently...
...
`)
builder.WriteString(agenticPromptText)
```

**What gets added:**
- XML tool schemas and detailed usage
- Pane targeting system
- Action guidelines
- Priority rules
- Response format rules

#### 3c. Custom Prompt File (`prompts.go:122-135`)
```go
agenticPrompt := m.Config.Prompts.Agentic
if m.Config.Prompts.AgenticPromptFile != "" {
    content, err := os.ReadFile(m.Config.Prompts.AgenticPromptFile)
    if err != nil {
        // error handling
    } else {
        agenticPrompt = string(content)
    }
}

if agenticPrompt != "" {
    builder.WriteString(agenticPrompt)
}
```

**What gets added:**
- Your Low-High Strategy prompt OR
- Aggressive Batch Strategy prompt OR
- Any other custom prompt file

### Step 4: Previous Conversation History (`process_message.go:57`)
```go
history = append(history, m.Messages...)
```

**What gets added:**
- ALL previous user messages (with their full context)
- ALL previous AI responses
- ALL previous command results
- ALL previous file contents

### Step 5: Current Message Building (`process_message.go:33-44`)

#### 5a. Repo Map Context
```go
repoMapContext := m.getRepoMapContext()
```
**What gets added:**
- Project structure tree
- File listings
- Directory organization
- Key files identification
- Generated by ctags

#### 5b. Tmux State
```go
currentTmuxWindow := m.GetTmuxPanesInXml(m.Config)
```
**What gets added:**
- Current window information
- ALL pane contents
- Pane IDs and layout
- Active pane indicator
- Shell environment info

#### 5c. User Input
```go
currentMessage := ChatMessage{
    Content:   repoMapContext + currentTmuxWindow + "\n\n" + execPaneEnv + "\n\n" + message,
    FromUser:  true,
    Timestamp: time.Now(),
}
```

### Step 6: Final Message Array Assembly (`process_message.go:59`)
```go
sending := append(history, currentMessage)
```

**Final array structure:**
1. **Message 1** (role=system): Complete system prompt
2. **Message 2** (role=user): First user message + context (if any history)
3. **Message 3** (role=assistant): First AI response (if any history)
4. **Message 4** (role=user): Second user message + context (if any history)
5. **...** (continues for all conversation history)
6. **Message N** (role=user): Current message + full current context

### Step 7: Context Size Check (`process_message.go:18-22`)
```go
if m.needSquash() {
    m.Println("Exceeded context size, squashing history...")
    m.squashHistory()
}
```

If the total context is too large, TmuxAI summarizes old messages to make room.

### Step 8: API Call (`process_message.go:61`)
```go
response, err := m.AiClient.GetResponseFromChatMessages(ctx, sending, m.GetOpenRouterModel())
```

The complete message array is sent to OpenRouter API.

## What Each Message Contains

### Message 1 (System Prompt) - Always First
```
[Your Custom Base System] +
[Agentic Instructions with XML Tools] +
[Your Low-High Strategy Prompt]
```

**Typical size:** ~3000-4000 tokens

### Message N (Current User Message) - Always Last
```
[Repo Map Context] +
[Complete Tmux State] +
[User's Actual Message]
```

**Typical size:** ~2000-8000 tokens

### Messages 2 to N-1 (Conversation History)
- Previous user messages (each with their full context at the time)
- Previous AI responses
- Previous command outputs
- Previous file contents

**Typical size:** ~1000-15000 tokens (grows with conversation length)

## Why Context Grows So Large

1. **Full History Every Time**: Each API call includes the complete conversation
2. **Rich Context**: Every user message includes repo map + tmux state
3. **File Contents**: Read files get added to conversation and persist
4. **Command Outputs**: Execution results get stored in history

## Example Context Flow

```
User: "check git status"

TmuxAI builds:
1. System prompt (3000 tokens)
2. Current message:
   - Repo map (1000 tokens)
   - Tmux state (500 tokens)  
   - "check git status" (3 tokens)
   
Total: ~4500 tokens

---

User: "read main.go"

TmuxAI builds:
1. System prompt (3000 tokens)
2. Previous user message + context (1500 tokens)
3. Previous AI response (200 tokens)
4. Current message:
   - Repo map (1000 tokens)
   - Tmux state (500 tokens)
   - "read main.go" (3 tokens)

Total: ~6200 tokens

---

After reading main.go:

TmuxAI builds:
1. System prompt (3000 tokens)
2. Previous conversation (1700 tokens)
3. File content message (2000 tokens)
4. Current message with context (1500 tokens)

Total: ~8200 tokens
```

## Key Files Involved

- **process_message.go**: Orchestrates the entire process
- **prompts.go**: Builds system prompts
- **manager.go**: Stores conversation history (`m.Messages`)
- **repomap.go**: Generates project context
- **tmux.go**: Captures current environment
- **ai_client.go**: Sends to OpenRouter API
- **config.go**: Provides custom prompt configuration

## Why Your Low-High Strategy Might Not Work

Your Low-High Strategy prompt gets appended AFTER:
1. Your custom base system prompt (which sets a different tone)
2. The agentic instructions (which have their own behavior rules)

The AI might be following the earlier instructions instead of your Low-High Strategy because they come first and set the initial behavior pattern.
